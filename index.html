03 — method

Completion is mechanical, not a vibe

Human votes say whether an artifact is good. They cannot say whether it is done. Every gate below is a program you can read, run, and disagree with.

GateWhat it checksCheat it kills
G1 input sealSHA-256 manifest of the fixture is captured before the run; the oracle re-reads the original, not the agent's copy.Deleting or rewriting the source data.
G2 held-out oracleTests and expected answers are not in the agent's workspace. They run after the agent stops.Editing the tests, hardcoding the visible expectations.
G3 coverage receiptThe deliverable must attest how many rows it processed. The oracle compares that count against ground truth.Sampling a tenth of the data and calling it done.
G5 provenanceTest files byte-identical after the run. No build tags, no skips. The diff may not touch the oracle.Disabling the check instead of fixing the code.
G7 leak scanOutput is scanned against fixture answer literals.Copying the answer key into the report.

G4 (network egress inside the agent sandbox) and G6 (two-pass determinism) are specified and not yet enforced. Every run record lists exactly the gates that actually ran, so a missing gate is visible rather than assumed.

What counts as cheating is a written contract

Dropping rows to go faster fails G3. Adding an index to a slow query passes, because the contract is about the result, not the method. The task file states that boundary before the model sees anything.

Reported separately, never blended

Completion rate, cost per valid pass, median wall-clock, and gate-failure rate are four numbers. There is no composite score, because a composite score is where gaming hides.

Votes are a different axis

Blind pairwise votes answer whether a passing artifact is usable. They never rescue a failing run and never move the completion number.
